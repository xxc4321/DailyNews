# JNBY News Watch Skill 设计规格

- 日期：2026-08-20
- 状态：已完成口头设计确认，等待书面规格复核
- V1 优先级：本地 Hermes + 飞书私聊稳定运行
- 默认时区：Asia/Shanghai
- 默认推送：每日 08:00，Top 10 新闻 + Top 5 Customer Voice

## 1. 背景

目标岗位负责 JNBY 海外客户生意伙伴关系、海外门店零售运营、产品培训、品牌 storytelling、本地化内容、客户团队培训及销售数据支持。情报系统需要持续追踪与这些职责相关的海外市场、服装设计与产品、零售门店、客户体验、供应商、物流、关税、开业活动、当地竞品和消费者反馈。

V1 运行于 Joe 本地 Hermes，由 DeepSeek API 提供语义评分和摘要，经 Hermes 原生 cron 每日调度并投递到飞书私聊机器人。系统同时支持每天多次手动调用和自定义数量、时间范围、焦点与成本模式。

## 2. 目标与非目标

### 2.1 目标

1. 每日北京时间 08:00 自动推送 Top 10 新闻和 Top 5 Customer Voice。
2. 新闻按岗位相关度排序，并用独立证据等级控制是否进入正式榜。
3. 客评按信号价值排序，并区分个案、形成中信号和高置信主题。
4. 每条内容均保留可打开的原文或原帖链接、发布时间、来源和评分解释。
5. 支持中文、英文、法语和意大利语发现与分析，输出统一为中文并保留原始标题。
6. 支持动态工作焦点，例如巴黎开店；焦点同时影响搜索词和排序权重。
7. 支持任意次数手动调用，如最近 7 天 20 条新闻和 10 条客评。
8. 在信源、DeepSeek 或飞书部分失败时可降级运行，并避免把失败记录为成功。
9. 核心输出使用稳定 JSON 和 Markdown，使 Skill 将来可被其他 Agent 或工作流复用。
10. 提供可重复的离线、DeepSeek API、Hermes cron 和飞书真实投递测试。

### 2.2 非目标

1. V1 不建设完整的 FreshRSS/Miniflux/RSSHub 自托管基础设施。
2. V1 不绕过社交平台登录、验证码、访问控制、robots 限制或平台授权要求。
3. V1 不把单条匿名评论表述为已证实的市场事实。
4. V1 不自动新增可信白名单信源；只生成候选建议，等待 Joe 确认。
5. V1 不自动充值 DeepSeek 余额，也不隐藏模型降级或数据缺口。
6. V1 不自动把临时手动查询写入长期动态焦点。
7. V1 不承诺绝对不存在错误、操纵或信息污染；它通过失败关闭、证据分层和审计链降低风险。

## 3. 已确认的产品决策

| 决策 | 结论 |
|---|---|
| V1 优先级 | 本地 Hermes + 飞书私聊稳定运行 |
| 总体架构 | 确定性采集/校验流水线 + DeepSeek 语义增强 + Hermes 适配器 |
| 信源策略 | 白名单主渠道 + 搜索发现层；发现结果必须回源 |
| 语言 | 中文、英文、法语、意大利语 |
| 动态焦点 | 自动建议、人工确认；显式命令可直接保存 |
| 输出深度 | 飞书短版 + 本地完整 Markdown/JSON |
| 新闻不足 | 正式区少发，候补区单列，不用低质量内容补数 |
| 手动参数 | 默认只对本次生效；明确“保存”才持久化 |
| 时间窗口 | 上次成功推送以来 + 72 小时补漏；手动可覆盖 |
| 多源核验 | 一般新闻单个可信原文；重大事件至少两个独立来源 |
| 白名单维护 | 自动提出候选，人工批准；官方源可快速放行 |
| 峰值手动调用 | 默认立即执行；省钱模式排队；紧急模式立即执行 |
| 验收级别 | 离线 + DeepSeek API + Hermes cron/飞书真实投递 |
| 早报分栏 | Top 10 新闻 + Top 5 Customer Voice，分别评分，不混排 |

## 6. 调用模式

### 6.1 定时早报

- Hermes cron：`0 8 * * *`，使用主机本地 Asia/Shanghai 时区。
- 默认数量：10 条新闻、5 个 Customer Voice 主题。
- 默认窗口：自上次成功投递以来的新内容，并回看 72 小时用于补漏。
- 定时模式隐藏已经成功推送且没有新增证据的事件。
- 只有投递成功后才更新 `last_successful_delivery_at` 和已推送状态。

### 6.2 手动调用

手动调用默认立即运行并返回完整榜单，即使部分内容当天已经在早报出现；这类内容显示“今日早报已推送”。支持：

- 自定义新闻数和客评数；
- 最近 24 小时、7 天或自定义日期；
- 临时国家、城市、行业、品牌或项目焦点；
- `immediate`、`budget`、`urgent` 成本模式；
- 展开某条内容为面试观点、行动建议或证据详情；
- 提议、确认、保存、停用或回滚动态焦点。

示例自然语言：

- “跑一下今日 JNBY 情报。”
- “给我最近 7 天 20 条新闻和 10 条客评。”
- “这次只看巴黎开店、物流和关税。”
- “把巴黎开店保存为未来 30 天重点。”
- “展开新闻第 3 条，给我面试可用的观点。”
- “省钱模式跑一次。”

### 6.3 CLI

CLI 和自然语言入口必须映射到同一运行请求结构。建议形态：

```powershell
python scripts/run.py digest --news 20 --reviews 10 --since 7d --focus paris --cost-mode immediate
python scripts/run.py focus propose --text "未来30天重点关注巴黎开店"
python scripts/run.py focus approve --id paris-store-opening
python scripts/run.py deepen --item-id <stable-id>
```

命令名称在实现阶段可以细化，但功能和默认行为不得改变。

## 7. 数据模型与审计链

### 7.1 新闻记录

每条规范化新闻至少包含：

- 稳定 ID、事件簇 ID；
- 原始标题、中文标题；
- 原文语言；
- 发布者、发布者层级；
- 发现 URL、最终 URL、canonical URL；
- 首次发布时间、页面更新时间、发现时间；
- 国家、城市、公司、品牌、主题实体；
- 摘要、相关度分、分项贡献、证据等级；
- 支持来源列表；
- 内容指纹；
- 安全/质量门结果；
- 是否已推送、推送运行编号和推送时间。

### 7.2 Customer Voice 记录与主题

单条评论记录至少包含：

- 稳定 ID、主题簇 ID；
- 平台、原帖 URL、发布时间、发现时间；
- 原文语言、短摘、中文释义；
- 国家/城市/门店或品牌；
- 体验主题、情绪标签；
- 公开或授权访问依据；
- 匿名化作者键，仅用于独立账号计数和去重；
- 操纵风险信号；
- 内容指纹和安全门结果。

主题簇至少包含：

- 主题名、信号分、置信度；
- 个案/形成中/高置信主题；
- 独立评论数、平台数、国家城市和时间跨度；
- 情绪分布；
- 最多 3 个代表性原帖链接；
- 可行动启示与限制说明。

### 7.3 运行记录

每次运行记录：

- 运行编号、调用来源、开始/结束时间；
- 时间窗口、数量、临时参数和生效焦点版本；
- 各信源成功、失败、重试和隔离状态；
- 候选数、正式数、去重数、候补数；
- DeepSeek 模型、调用数、缓存命中/未命中 token、输出 token；
- 价格快照时间和估算费用；
- 输出路径、飞书投递目标、投递结果和幂等键。

## 8. 信源系统

### 8.1 新闻信源层级

- S0：JNBY/江南布衣官网和投资者关系、港交所、政府、海关、税务、监管、商场、品牌和供应商一手公告。
- S1：经批准的国际通讯社、主流财经媒体、服装/时尚行业媒体和当地零售媒体。
- S2：Tavily、Brave/SearXNG、GDELT、Google News、RSSHub 等发现渠道。

S2 只发现线索。候选必须解析到最终原文 URL 并通过内容、日期和来源校验，才能升级到正式新闻。

### 8.2 Customer Voice 适配器

优先顺序：

1. 官方或公开 API；
2. RSS/Atom；
3. Joe 授权的导出文件或数据接口；
4. 搜索发现后可公开打开的原帖。

Instagram、TikTok、X、小红书、微博等封闭平台没有合法稳定接口时，适配器保持禁用或只做发现，不通过浏览器伪装、登录绕过或验证码规避进行采集。

### 8.3 信源治理

`sources.yaml` 记录域名、发布者、国家、语言、内容类型、层级、授权方式、健康状态、最后检查时间和风险备注。自动发现的新来源写入 `proposals/sources/`，人工确认后才进入正式白名单。官方一手源可快速批准，但仍保留变更记录。

域名跳转、证书异常、内容类型突变、长期失效或污染比例升高时自动隔离，并提出替代来源建议；不自动替换为未知镜像。

## 9. 采集、回源和规范化

1. 根据基础画像、动态焦点、语言和时间窗口生成多组查询。
2. 并行读取一手 RSS/API、批准媒体源和发现渠道。
3. 对每个候选解析最终 URL，移除追踪参数并读取 canonical URL。
4. 提取标题、正文、发布日期、更新时间、发布者和语言。
5. 将原文保存为短摘、结构化事实和内容哈希；不批量归档完整受版权保护正文。
6. 规范化国家、城市、品牌、主题和多语言同义词。
7. 新闻按 URL、标题、实体、时间和正文指纹去重聚类。
8. 评论按文本指纹、匿名化作者、时间和主题聚类。
9. 经过各自质量门后进入确定性预评分。
10. 合格候选按批次交给 DeepSeek，返回严格 JSON。
11. 将确定性结果和语义结果合并，生成最终排序和输出。

## 10. 新闻可信门

### 10.1 正式新闻最低条件

- 最终 URL 可公开访问；
- 发布者为 S0/S1，或 S2 发现后已回源到 S0/S1；
- 标题、正文和日期一致；
- 在时间窗口内，或作为 72 小时补漏且未成功推送；
- 内容不是纯聚合页、搜索摘要、无来源转载或明显内容农场；
- 安全清洗通过；
- 一般新闻至少一个可信原文；
- 重大政策、关税、供应链中断、门店经营或声誉事件至少两个独立来源。

两个复制同一通讯社稿或同一新闻稿的站点只计一个独立来源。独立性通过所有权、原始出处、正文相似度和引用链综合判断。

### 10.2 证据等级

- A：官方一手源，或重大事件通过两个独立可信来源核验。
- B：单个可信媒体/行业媒体原文，适用于普通新闻。
- C：仅搜索摘要、转载、匿名来源或无法完整回源；只能进入候补区。

## 11. Customer Voice 信号门

客评不以“事实新闻”标准淘汰，而以“是否可作为消费者信号”判断：

- 必须有原帖或授权导出记录；
- 必须有平台和时间；
- 必须能区分独立账号，且在输出中匿名化；
- 过滤重复文案、促销链接、营销账号和异常爆发；
- 不因负面情绪本身降权；
- 单条体验保留为个案，不外推为趋势；
- 多个独立账号重复出现可升级为形成中信号；
- 多平台、跨时间重复出现可升级为高置信主题；
- 涉及安全、歧视或严重服务事故的单条评论可以高优先级提示，但必须标明尚未交叉验证。

“个案/形成中/高置信”的数量阈值写入配置并可调整。V1 默认：1 个独立账号为个案；至少 3 个独立账号为形成中；至少 5 个独立账号，且覆盖 2 个平台或至少两个相隔 24 小时的采集批次，才标记为高置信。严重事件例外不改变置信标签。

## 12. 评分模型

### 12.1 新闻基础相关度

| 维度 | 默认权重 |
|---|---:|
| JNBY、集团品牌、直接竞品 | 22 |
| 已布局或准备进入的国家、城市 | 18 |
| 服装、设计、面料、产品故事 | 12 |
| 零售、门店、客户体验、培训 | 16 |
| 供应商、物流、关税、库存 | 14 |
| 批发客户、品牌传播、数据运营等岗位能力 | 10 |
| 时效性与业务影响 | 8 |

证据等级不混入相关度分数，而是进入资格门和同分排序。

有动态焦点时：

```text
最终相关度 = 75% 基础相关度
           + 25% 当前焦点匹配度
           + 重大事件加分（0-10）
           - 垃圾/操纵风险扣分（0-20）
```

最终分数截断在 0-100。重大事件加分分为 0、5、10 三档：普通业务动态为 0；开店/闭店、重要合作、明确供应商或库存变化为 5；新监管、关税变化、安全事故、重大供应中断或严重声誉事件为 10。严重垃圾、提示注入或来源异常直接不通过资格门，不仅依赖扣分。没有动态焦点时直接使用完整基础相关度，不做 75% 折损。

### 12.2 Customer Voice 信号分

| 维度 | 默认权重 |
|---|---:|
| 与岗位/当前焦点相关性 | 30 |
| 体验描述具体程度 | 20 |
| 独立客评重复出现程度 | 20 |
| 可行动性 | 15 |
| 时效性 | 10 |
| 互动量 | 5 |
| 疑似刷评、重复文案、营销账号、异常爆发 | 最多扣 30 |

情绪为正面/中性/负面/混合标签，不直接加分。信号分和置信标签分别展示。

### 12.3 可解释性

每条正式内容必须给出分项贡献和扣分原因，例如：

```text
89 分 = 巴黎焦点 +18、线下开店 +15、法国物流 +12、
          零售运营 +14、时效性 +8、其他基础匹配 +22；证据 A
```

## 13. 动态焦点

每个焦点包含：

- ID、名称、状态；
- 开始时间、截止时间、衰减天数；
- 国家、城市、品牌、竞品、主题和多语言词组；
- 焦点强度（0-100，用于焦点内部匹配；动态焦点在最终新闻分数中的总占比仍封顶 25%）；
- 提议来源、人工确认记录和回滚编号。

Skill 可以根据聊天或项目资料提出焦点建议，但只能写入 `proposals/focus/`。Joe 回复“确认焦点”或明确说“保存”后才更新 `focus.yaml`。

未指定期限时默认有效 30 天，最后 7 天线性衰减。焦点到期后保留历史记录但不参与查询和评分。

“巴黎新店”焦点至少包含：巴黎、法兰西岛、法国；选址、租约、装修、招聘、开业和门店运营；物流、清关、关税、退货、库存和本地供应商；开业活动、艺术合作、媒体预热和 KOL；巴黎当地设计师品牌、买手店和服装门店；中文、英文、法语、意大利语同义词。

## 14. DeepSeek 与成本控制

### 14.1 模型策略

- 默认模型可配置，首选 `deepseek-v4-flash` 非思考模式。
- 来源冲突、重大政策、复杂供应链或严重客评才升级为 Pro/思考模式。
- 每次运行先确定性过滤，再批量调用模型；常规上限为两次模型调用。
- 固定提示词、评分规则和 JSON Schema 位于稳定前缀；动态内容置后，以提高缓存命中概率。
- 限制候选数量、每篇短摘长度和最大输出 token。
- DeepSeek 输出必须通过本地 JSON Schema/字段校验，模型不能直接修改白名单、焦点或投递状态。

### 14.2 峰谷价

DeepSeek 当前官方说明：峰值时段为 UTC 01:00-04:00 和 06:00-10:00，即北京时间 09:00-12:00 和 14:00-18:00；其余为低峰，低峰价格为峰值的一半。每日 08:00 处于低峰。价格可能调整，因此估算必须记录价格快照时间和来源。

### 14.3 成本模式

- `immediate`：手动调用默认模式，立即执行。
- `budget`：峰值时段可排队到下一个低峰；定时早报仍按 08:00 执行。
- `urgent`：立即执行，允许按升级规则使用更强模型。

系统不自动充值。达到配置的调用或 token 软上限后，必须清晰标注并使用确定性回退或等待用户选择。

## 15. 安全边界

1. 外部网页、RSS、API 和评论内容始终视为不可信数据，不能改变系统指令或触发工具动作。
2. 仅允许 HTTP/HTTPS；禁止 `file:` 等本地协议。
3. 初始 URL 和每次跳转都解析并阻止 localhost、环回、链路本地、私有网段和本机资源，降低 SSRF 风险。
4. 强制 TLS 验证、跳转上限、响应大小上限、连接/读取超时和允许的内容类型。
5. 移除脚本、样式、隐藏节点、HTML 注释、零宽字符和可疑指令片段。
6. 采集进程无 shell 执行、配置写入或凭据读取能力；持久化由受限的状态层完成。
7. 不在报告和日志中记录 API Key、飞书 Secret、完整用户资料或不必要的个人信息。
8. 评论作者使用单向匿名键去重；飞书默认不展示完整用户名。
9. 原文只保留必要短摘、结构化字段和哈希，避免批量复制受版权保护全文。

## 16. 输出与飞书投递

### 16.1 飞书结构

1. 今日概览：时间窗口、一句话主线、动态焦点、成功/失败信源、模型和估算费用。
2. Top 10 新闻：标题、原文语言、日期、国家城市、相关度、证据等级、中文摘要、加分原因和原文链接；重大事件增加第二来源。
3. Top 5 Customer Voice：主题、信号分、置信度、情绪分布、独立评论数、平台地区、可行动启示和代表性原帖链接。
4. 候补区：未过正式门但值得关注的线索和失败原因。

长内容每条消息最多 5 个项目并自动分页。完整 JSON、Markdown 和运行日志保存在本地。

### 16.2 幂等投递

报告幂等键由日期、时间窗口、配置版本和内容摘要生成。飞书成功后写入投递记录；失败时保留本地报告并允许用同一幂等键重试。创建正式 cron 前必须检查现有任务并复用或更新唯一匹配项，避免重复创建。

## 17. 失败处理

- 单一信源失败：最多重试两次并指数退避，本次跳过，其他来源继续。
- 发现服务失败：切换其他发现渠道；一手 RSS/API 继续运行。
- DeepSeek 非法 JSON：用更严格请求重试一次；仍失败则使用确定性评分并标注“语义增强不可用”。
- DeepSeek 网络、余额或限流失败：保存候选和运行状态，不阻断可生成的确定性日报。
- 可信新闻不足 10 条：正式区少发，候补区单列。
- 网络中断：不把缓存旧闻冒充新消息；发送运行状态或保存待重试任务。
- 飞书失败：不更新成功时间和已推送状态；恢复后幂等重试。
- 定时与手动任务并行：SQLite 使用事务/WAL；每次运行有独立运行编号。
- 信源健康下降：隔离并提出替代建议，不自动修改白名单。

## 18. 测试与验收

### 18.1 离线测试

固定测试样本覆盖中文、英文、法语、意大利语新闻和客评，并验证：

1. 默认 10/5 和自定义 20/10 数量；
2. 巴黎焦点提升巴黎、开店、物流、关税、开业活动和竞品内容；
3. 焦点到期、衰减和回滚恢复基础排序；
4. URL、标题、实体和正文指纹去重；
5. 复制通讯社稿不计为两个独立来源；
6. 正式区、候补区和重大事件双源门；
7. 旧闻修改更新时间不冒充新热点；
8. 个案、形成中和高置信客评主题；
9. 刷评爆发、重复话术、营销链接和异常账号信号；
10. 提示注入、隐藏文本、非法协议、内网 IP、恶意跳转和超大响应；
11. DeepSeek 非法 JSON、超时、余额/限流失败和确定性回退；
12. 飞书失败、幂等重试和状态不误写；
13. 价格快照、token 用量和费用估算；
14. 定时与手动并发下的 SQLite 一致性。

### 18.2 DeepSeek API 实测

- 使用现有 Hermes/环境凭据完成至少一次真实批量评分；
- 校验严格 JSON、字段完整性、token 用量和估算费用；

- 将模型调用限制在已配置预算内。

### 18.3 Hermes 与飞书实测

1. 检查 Hermes 版本、Gateway、Feishu 配置存在性和现有 cron，不输出密钥。

### 18.4 完成条件

- Skill 结构通过官方快速校验；
- 所有离线测试通过；
- DeepSeek 实测通过或明确记录因缺少现有凭据无法执行；
- 飞书真实投递通过或明确记录因缺少现有配置无法执行；
- Hermes 正式 cron 唯一且下一次运行时间正确；
- 手动 10/5、20/10、临时焦点、保存焦点、省钱和紧急模式可用；
- 报告可追溯到原文链接并显示评分解释；
- 安全测试证明危险内容进入隔离/候补而不会被执行；
- 交付安装路径、操作示例、测试报告、cron 状态和已知限制。

## 20. 已知限制

1. Instagram、TikTok、X、小红书、微博等平台覆盖取决于合法 API、公开索引或授权数据，V1 无法保证全量。
2. 付费墙、地区限制和动态渲染会导致部分原文只能进入候补区。
3. 评论账号真实性无法由公开数据完全证明，系统只能提供可解释置信指标。
4. DeepSeek 价格、模型名和平台 API 规则会变化，必须通过配置和健康检查维护。
5. 多语言情绪与讽刺识别存在误差，Customer Voice 输出必须显示样本量和代表性限制。
6. 规格确认后，Joe 创建并明确授权发布到 `https://github.com/xxc4321/DailyNews`；仓库只包含可复用源码、配置模板、文档与测试，排除密钥、运行数据库、缓存、生成报告和虚拟环境。
